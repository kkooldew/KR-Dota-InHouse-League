# 도타 2 인하우스 리그 사이트

선수 등록, 공개 순위, 운영진 관리를 하는 사이트입니다. GitHub Pages에 그대로 올려 쓰고, 등록 정보와 공개 기록은 운영진 구글 계정의 구글 시트(Apps Script)에 저장합니다.

| 파일 | 하는 일 | 누가 보나 |
|---|---|---|
| `index.html` | 선수 등록 (닉네임, 스팀 프로필, 디스코드, MMR, 포지션 순서) | 누구나 |
| `ranking.html` | 순위와 경기 기록 | 누구나 |
| `admin.html` | 등록 명단 확인·승인, 등록 열기·닫기, 매니저용 명단 받기 | 운영진 키가 있는 사람 |
| `config.js` | 서버 주소, 디스코드 초대 링크 같은 공개 설정 | |
| `apps-script/Code.gs` | 구글 시트에 붙여 쓰는 서버 코드 | |
| `bot/` | 디스코드 내전 모집 봇 | |
| `records.json` | 서버를 연결하지 않았을 때 순위 페이지가 읽는 기록 | |
| `manager/` | 리그 매니저 (팀 편성·경기 기록). 운영진 컴퓨터에서 파일로 엽니다 | 운영진 |
| `tests/` | 서버 코드 테스트 (`node tests/apps-script.test.js`) | |
| `CLAUDE.md` | Claude Code가 이 프로젝트를 이어받을 때 읽는 안내 | |

리그 매니저 파일에는 선수 데이터나 운영진 키가 들어 있지 않아서 저장소에 함께 둬도 괜찮습니다. 기록은 각자의 브라우저에 저장되고, 공개 페이지에 올리려면 운영진 키가 필요합니다.

## 데이터 흐름

```
선수 ──등록──▶ index.html ──▶ 구글 시트 (운영진만 열람)
                                   │
운영진 ◀── admin.html ◀────────────┤  승인, 매니저용 명단 받기
                                   │
디스코드 봇 ──참가 명단──────────▶ │ ──▶ 리그 매니저 (팀 편성, 결과 기록)
                                   │            │
누구나 ◀── ranking.html ◀── 공개 기록 ◀─────────┘  (디스코드·스팀 정보는 빠짐)
```

## 1. 구글 시트 서버 만들기 (처음 한 번)

1. 구글 드라이브에서 새 스프레드시트를 만듭니다. 이름은 `인하우스 리그 서버`처럼 아무렇게나 지어도 되고, **누구에게도 공유하지 않습니다.**
2. 메뉴의 **확장 프로그램 → Apps Script**를 엽니다. 편집기에 있는 기본 코드를 모두 지우고 `apps-script/Code.gs` 내용을 붙여넣은 뒤 저장합니다.
3. 위쪽 함수 목록에서 `setup`을 고르고 **실행**을 누릅니다. 권한을 묻는 창이 뜨면 내 계정을 고르고, "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 눌러 허용합니다. 내가 붙여넣은 내 코드라서 이 경고가 뜹니다.
4. 아래 **실행 로그**에 나온 `운영진 키`를 복사해 안전한 곳에 둡니다. 나중에 다시 보려면 왼쪽 톱니바퀴(프로젝트 설정) 아래 **스크립트 속성**의 `ADMIN_KEY`를 보면 됩니다.
5. 오른쪽 위 **배포 → 새 배포**를 누르고 유형을 **웹 앱**으로 고릅니다.
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
6. **배포**를 누르면 나오는 `https://script.google.com/macros/s/…/exec` 주소를 복사합니다.

"모든 사용자"로 열어야 등록 페이지와 순위 페이지가 서버를 쓸 수 있습니다. 시트 자체는 공개되지 않고, 등록 명단은 운영진 키가 있어야만 돌려줍니다.

`Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 눌러야 반영됩니다. 이렇게 하면 주소가 바뀌지 않습니다.

## 2. GitHub Pages에 올리기

1. GitHub에서 **Public** 저장소를 만듭니다.
2. 이 폴더의 파일을 모두 올립니다 (**Add file → Upload files**에 폴더째 끌어다 놓기). `bot/config.json`은 올리지 마세요.
3. 저장소에서 `config.js`를 열고 연필 버튼으로 `apiUrl: ''` 따옴표 안에 1-6에서 복사한 주소를 넣고 저장합니다. 디스코드 초대 링크와 선물 안내 문장도 여기서 바꿉니다.
4. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 Save를 누릅니다.
5. 1~2분 뒤 `https://아이디.github.io/저장소이름/`이 등록 페이지가 됩니다. 순위는 `ranking.html`, 운영진은 `admin.html`입니다.

## 3. 리그 매니저 연결

1. `manager/InhouseLeagueManager_v0_18.html`을 엽니다. 이전 버전을 쓰던 브라우저라도 저장소가 달라질 수 있으니, v0.17에서 **기록 저장**으로 파일을 받아 v0.18의 **데이터 · 설정 → 저장한 기록 되살리기**로 옮기는 것이 안전합니다.
2. **데이터 · 설정 → 공개 페이지 연결**에 서버 주소와 운영진 키를 넣고 **연결 확인**을 누릅니다.
3. **기록이 바뀌면 자동으로 올리기**를 켜면 경기를 기록하거나 되돌릴 때마다 몇 초 뒤 순위 페이지에 반영됩니다.

## 4. 디스코드 봇

`bot/config.example.json`을 같은 폴더에 `config.json`으로 복사해 토큰, 서버·채널 ID를 채웁니다. `sync_url`에 서버 주소, `sync_key`에 운영진 키를 넣으면 모집이 끝날 때 명단이 서버에도 올라가서, 매니저에서 **봇이 올린 명단 불러오기**로 바로 받을 수 있습니다. 비워 두면 관리자 채널에 올라오는 "매니저 붙여넣기용" 명단을 복사해 붙여넣으면 됩니다.

```
pip install -r bot/requirements.txt
python bot/bot.py
```

## 5. 시즌 운영 흐름

1. 운영진 페이지에서 시즌 이름을 정하고 **등록 열기** 상태인지 확인한 뒤, 디스코드에 등록 페이지 주소를 공지합니다.
2. 운영진 페이지에서 등록자를 확인하고 **승인** 또는 **제외**를 고릅니다. 디스코드 역할은 직접 부여합니다.
3. **매니저용 명단 받기**로 파일을 받아 매니저 선수단 탭의 **CSV 파일 고르기**로 불러옵니다. 시즌 중에 새로 승인한 선수가 생기면 같은 방법으로 다시 불러오면 새 선수만 더해집니다.
4. 내전마다: 관리자 채널에서 `/내전생성` → 5분 뒤 봇이 명단 공지 → 매니저 팀 편성 탭의 **디스코드 참가 명단으로 고르기**에서 명단을 불러오거나 붙여넣기 → **팀 짜기** → 경기 후 승리 팀 기록.
5. 하루가 끝나면 매니저 위쪽 **기록 저장**으로 백업 파일을 받아 둡니다.
6. 등록 기간이 끝나면 운영진 페이지에서 **등록 닫기**를 누릅니다.

## 보안과 개인 정보

- 등록 정보(스팀, 디스코드)는 운영진 구글 시트에만 저장됩니다. 시트를 공유하지 마세요.
- 공개 순위 페이지에는 닉네임, MMR, 지망, 전적, 경기 기록만 올라갑니다. 서버에서 한 번 더 걸러냅니다.
- 운영진 키가 새어 나갔다면 Apps Script 편집기에서 `resetAdminKey`를 실행해 새 키를 만들고, 운영진 페이지·매니저·봇의 키를 바꿉니다.
- 같은 스팀 프로필은 처음 등록한 디스코드 계정으로만 고칠 수 있고, 닉네임은 다른 선수와 겹칠 수 없습니다. 디스코드 계정이 바뀐 선수는 시트에서 직접 고쳐 주세요.
- 같은 스팀 프로필로는 30초에 한 번만 제출할 수 있고, 사람 눈에 보이지 않는 칸으로 자동 입력 프로그램을 거릅니다.

## 알아 둘 점

- Apps Script는 무료로 쓰는 대신 하루 실행량에 한도가 있습니다. 순위 페이지는 2분마다 새 기록을 확인하는데, 리그 규모에서는 넉넉합니다. 접속자가 많아지면 `config.js`의 `refreshSeconds`를 늘리세요.
- 서버를 연결하지 않으면 순위 페이지는 같은 폴더의 `records.json`을 읽습니다. 이때는 매니저에서 받은 기록 파일을 이 이름으로 올려 갱신할 수 있습니다.
