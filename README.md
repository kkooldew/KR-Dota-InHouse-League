# 도타 2 인하우스 리그 사이트

선수 등록, 공개 순위, 운영진 관리를 하는 사이트입니다. GitHub Pages에 그대로 올려 쓰고, 등록 정보와 공개 기록은 운영진 구글 계정의 구글 시트(Apps Script)에 저장합니다.

| 파일 | 하는 일 | 누가 보나 |
|---|---|---|
| `index.html` | 첫 화면(시즌과 모집 여부, **시작하기**)과 선수 등록 양식(닉네임, 스팀 프로필, 디스코드, 현재 MMR, 최고 MMR, 포지션 순서) | 누구나 |
| `ranking.html` | 순위와 경기 기록 | 누구나 |
| `admin.html` | 등록 명단 확인·승인, 등록 열기·닫기, 새 시즌 시작, 리그 매니저 열기, 매니저용 명단 받기 | 운영진 키가 있는 사람 |
| `config.js` | 서버 주소, 디스코드 초대 링크 같은 공개 설정 | |
| `apps-script/Code.gs` | 구글 시트에 붙여 쓰는 서버 코드 | |
| `bot/` | 디스코드 내전 모집 봇 | |
| `records.json` | 서버를 연결하지 않았을 때 순위 페이지가 읽는 기록 | |
| `manager/` | 리그 매니저 (팀 편성·경기 기록). 운영진 페이지의 **리그 매니저 열기**나 `…/manager/` 주소로 엽니다 | 운영진 |
| `tests/` | 서버 코드 테스트 (`node tests/apps-script.test.js`), 봇 테스트 (`python tests/bot.test.py`) | |
| `CLAUDE.md` | Claude Code가 이 프로젝트를 이어받을 때 읽는 안내 | |

리그 매니저 파일에는 선수 데이터나 운영진 키가 들어 있지 않아서 저장소에 함께 둬도 괜찮습니다. 기록은 각자의 브라우저에 저장되고, 공개 페이지에 올리려면 운영진 키가 필요합니다.

## 데이터 흐름

```
선수 ──등록──▶ index.html ──▶ 구글 시트 (운영진만 열람)
                                   │
운영진 ◀── admin.html ◀────────────┤  승인, 매니저용 명단 받기
                                   │
디스코드 봇 ──참가 명단──────────▶ │ ──▶ 리그 매니저 (팀 편성, 결과 기록)
                                   │            │
누구나 ◀── ranking.html ◀── 공개 기록 ◀─────────┘  (디스코드·스팀 정보는 빠짐)
```

## 1. 구글 시트 서버 만들기 (처음 한 번)

1. 구글 드라이브에서 새 스프레드시트를 만듭니다. 이름은 `인하우스 리그 서버`처럼 아무렇게나 지어도 되고, **누구에게도 공유하지 않습니다.**
2. 메뉴의 **확장 프로그램 → Apps Script**를 엽니다. 편집기에 있는 기본 코드를 모두 지우고 `apps-script/Code.gs` 내용을 붙여넣은 뒤 저장합니다.
3. 위쪽 함수 목록에서 `setup`을 고르고 **실행**을 누릅니다. 권한을 묻는 창이 뜨면 내 계정을 고르고, "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 눌러 허용합니다. 내가 붙여넣은 내 코드라서 이 경고가 뜹니다.
4. 아래 **실행 로그**에 나온 `운영진 키`를 복사해 안전한 곳에 둡니다. 나중에 다시 보려면 왼쪽 톱니바퀴(프로젝트 설정) 아래 **스크립트 속성**의 `ADMIN_KEY`를 보면 됩니다.
5. 오른쪽 위 **배포 → 새 배포**를 누르고 유형을 **웹 앱**으로 고릅니다.
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
6. **배포**를 누르면 나오는 `https://script.google.com/macros/s/…/exec` 주소를 복사합니다.

"모든 사용자"로 열어야 등록 페이지와 순위 페이지가 서버를 쓸 수 있습니다. 시트 자체는 공개되지 않고, 등록 명단은 운영진 키가 있어야만 돌려줍니다.

`Code.gs`를 고친 뒤에는 편집기에 새 코드를 붙여넣고 저장한 다음, `setup`을 한 번 실행하고(새로 필요한 권한을 허용합니다. 운영진 키는 바뀌지 않습니다) **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 눌러야 반영됩니다. 이렇게 하면 주소가 바뀌지 않습니다.

## 2. GitHub Pages에 올리기

1. GitHub에서 **Public** 저장소를 만듭니다.
2. 이 폴더의 파일을 모두 올립니다 (**Add file → Upload files**에 폴더째 끌어다 놓기). `bot/config.json`은 올리지 마세요.
3. 저장소에서 `config.js`를 열고 연필 버튼으로 `apiUrl: ''` 따옴표 안에 1-6에서 복사한 주소를 넣고 저장합니다. 디스코드 초대 링크와 선물 안내 문장도 여기서 바꿉니다.
4. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 Save를 누릅니다.
5. 1~2분 뒤 `https://아이디.github.io/저장소이름/`이 등록 페이지가 됩니다. 순위는 `ranking.html`, 운영진은 `admin.html`입니다.

## 3. 리그 매니저 연결

**운영진은 링크로 엽니다.** 운영진 페이지(`admin.html`)에 운영진 키로 들어가 **리그 매니저 열기**를 누르면 매니저가 새 탭에 열립니다. 주소는 `https://아이디.github.io/저장소이름/manager/`이고, 즐겨찾기에 넣어 두고 바로 열어도 됩니다.

- 그 버튼으로 열면 매니저가 이 서버에 이어진 채로 열립니다. 서버 주소와 운영진 키를 매니저에 다시 넣을 필요가 없습니다(로그인할 때 **이 브라우저에 기억하기**를 켠 경우. 껐다면 매니저의 **데이터 · 설정 → 리그 서버 연결**에 운영진 키만 한 번 넣습니다).
- 매니저를 처음 여는 브라우저에서는 열자마자 서버의 기록(선수단, 경기, 설정)을 받아 옵니다. 그래서 운영진 누구나 자기 컴퓨터에서 같은 기록을 보고 고칠 수 있습니다.
- 이미 매니저를 쓰던 브라우저(기록이 들어 있는 브라우저)에서는 서버 주소와 키만 채워 주고, **서버와 자동으로 맞추기**는 켜지 않습니다. 그 브라우저의 기록과 서버의 기록 가운데 어느 쪽을 남길지 운영진이 정해야 하기 때문입니다. 데이터 · 설정 탭에서 직접 켜 주세요.
- 매니저 화면은 주소를 아는 사람이면 누구나 열 수 있지만, 운영진 키가 없으면 서버의 기록을 읽지도 고치지도 못하는 빈 프로그램일 뿐입니다.

파일로 열거나 직접 연결하려면:

1. `manager/InhouseLeagueManager_v0_18.html`을 엽니다. 이전 버전을 쓰던 브라우저라도 저장소가 달라질 수 있으니, v0.17에서 **기록 저장**으로 파일을 받아 v0.18의 **데이터 · 설정 → 저장한 기록 되살리기**로 옮기는 것이 안전합니다.
2. **데이터 · 설정 → 리그 서버 연결**에 서버 주소와 운영진 키를 넣고 **연결 확인**을 누릅니다.
3. **서버와 자동으로 맞추기**를 켭니다. 서버에 기록이 없으면 이 브라우저의 기록이 첫 기록으로 올라갑니다.

파일로 연 매니저와 링크로 연 매니저는 브라우저가 서로 다른 곳으로 보아서, 저장해 둔 기록과 연결 설정을 따로 갖습니다. 둘 다 서버에 이어 두면 같은 기록을 봅니다.

연결한 뒤에는 **기록의 원본이 서버**에 있습니다. 매니저에서 고친 것은 몇 초 뒤 서버에 올라가고, 봇이 `/승리`로 기록한 경기 결과는 서버에서 매니저로 들어옵니다. 어느 컴퓨터에서 매니저를 열어도 서버 주소와 운영진 키만 넣으면 같은 기록이 보입니다.

- 매니저에서 고쳐 놓고 아직 올리지 못한 사이에 서버 기록도 바뀌었다면(봇이 결과를 기록했다면), 덮어쓰지 않고 어느 쪽을 남길지 묻습니다. 보통은 서버 기록을 불러오면 됩니다.
- 서버는 기록을 받을 때마다 순위 페이지와 시트의 **순위**, **경기 기록** 탭을 다시 씁니다. 두 탭은 보기용입니다. MMR과 전적은 경기마다 이어서 계산한 값이라 시트에서 고쳐도 다시 계산되지 않고, 다음에 기록이 바뀔 때 지워집니다. 고칠 때는 매니저를 쓰세요.
- 매니저 위쪽 **기록 저장**으로 받는 백업 파일은 그대로 쓸 수 있습니다. 가끔 받아 두세요.

## 4. 디스코드 봇

`bot/config.example.json`을 같은 폴더에 `config.json`으로 복사해 토큰, 서버·채널 ID를 채웁니다. `sync_url`에 서버 주소, `sync_key`에 운영진 키를 넣으면 모집이 끝날 때 명단이 서버에도 올라가서, 매니저에서 **봇이 올린 명단 불러오기**로 바로 받을 수 있습니다. 비워 두면 관리자 채널에 올라오는 "매니저 붙여넣기용" 명단을 복사해 붙여넣으면 됩니다.

```
pip install -r bot/requirements.txt
python bot/bot.py
```

윈도우에서는 `bot/run_bot.bat`을 더블클릭해도 켜집니다. 검은 창에 "로그인 완료"와 채널·권한 확인 결과가 나오면 준비된 것이고, 창을 닫으면 봇이 꺼집니다. 봇은 한 곳에서만 켜 두세요.

참여 신청 채널(`signup_channel_id`)은 포럼 채널과 일반 채팅 채널을 모두 쓸 수 있습니다. 포럼이면 내전마다 새 글이 생기고, 참가자는 그 글 안에서 `/참여`를 입력합니다. 글 본문에 마감 시각과 참여자 명단이 나오고, 마감하면 글이 잠깁니다.

| 명령어 | 입력하는 곳 | 하는 일 |
|---|---|---|
| `/내전생성` | 관리자 채널 | 모집을 시작합니다. 마감은 모집 시간(`signup_minutes`, 기본 5분) 뒤를 분 단위로 올림한 시각입니다. 12:00:30에 만들면 12:06:00에 마감합니다. |
| `/내전생성 마감:2026-10-07-21-30` | 관리자 채널 | 적은 시각(연-월-일-시-분, 한국 시간, 24시간제)에 마감하는 모집을 만듭니다. 형식이 틀리거나 이미 지난 시각이면 만들지 않습니다. |
| `/마감` | 관리자 채널 | 지금까지 모인 인원으로 바로 마감합니다. |
| `/연장` | 관리자 채널 | 마감을 `extend_minutes`(기본 5분) 뒤로 미룹니다. 마감한 뒤에 쓰면 모집을 다시 엽니다. |
| `/취소` | 관리자 채널 | 이번 내전을 취소하고 참여자에게 알립니다. |
| `/시작` | 관리자 채널 | 로비 음성 채널에 있는 선수를 배정된 팀(래디언트·다이어)의 음성 채널로 옮깁니다. 아래 "음성 채널 이동"을 보세요. |
| `/종료` | 관리자 채널 | 래디언트·다이어 음성 채널에 있는 사람을 모두 로비 음성 채널로 옮깁니다. |
| `/승리` | 관리자 채널 | 이긴 팀(래디언트·다이어)을 골라 경기 결과를 기록합니다. 봇이 공지한 편성 그대로 승패와 MMR을 정산하고, 모집 글에 선수별 MMR 변동을 올립니다. 팀만 짜고 경기를 하지 않은 판은 **경기 안 함**을 골라 기록 없이 정리합니다. |
| `/승리취소` | 관리자 채널 | `/승리`로 기록한 마지막 결과를 되돌립니다. 잘못 골랐을 때 씁니다. |
| `/선수역할 역할:@역할` | 관리자 채널 | 승인한 선수에게 자동으로 줄 역할을 정합니다. 아래 "참여 선수 역할 자동 부여"를 보세요. |
| `/참여`, `/참여취소` | 모집 글 (일반 채널이면 그 채널) | 참여를 신청하거나 취소합니다. |

봇에는 채널 보기, 메시지 보내기(포럼에서는 글 올리기), 스레드에서 메시지 보내기, 스레드 관리(글 잠그기) 권한이 필요합니다. 관리자 채널이나 포럼이 비공개라면 그 채널에 봇을 따로 넣어 주세요. 진행 중인 모집은 `bot/state.json`에 적어 두므로 봇을 껐다 켜도 이어지고, 꺼져 있는 사이 마감 시각이 지났으면 켜자마자 마감합니다.

운영진 명령어로 봇이 올리는 글은 모두 그 명령어를 쓴 운영진의 멘션으로 시작합니다. 예) `@꿀듀님이 모집을 연장했어요! 오후 9:35까지 /참여 로 신청하세요.`, `@꿀듀: 게임이 종료되어 모든 선수를 로비로 이동시킵니다.` 누가 한 일인지 모집 글에서도 보이게 하려는 것이고, 그 운영진에게 알림이 울리지는 않습니다. 마감 시각이 되어 봇이 저절로 마감할 때의 글과, 명령어를 쓴 본인에게만 보이는 안내에는 붙지 않습니다.

### 음성 채널 이동 (`/시작`, `/종료`)

경기를 시작할 때 `/시작`을 입력하면 봇이 **로비 음성 채널에 있는 선수**를 팀 편성 공지대로 래디언트·다이어 음성 채널로 옮기고, 모집 글에 "게임이 시작되어 선수들을 각자의 음성 채널로 이동시킵니다."라고 알립니다. 경기가 끝나고 `/종료`를 입력하면 래디언트·다이어 음성 채널에 있는 사람을 (선수가 아니어도) 모두 로비로 옮기고 "게임이 종료되어 모든 선수를 로비로 이동시킵니다."라고 알립니다.

1. 디스코드 **서버 설정 → 역할**에서 봇의 역할(퍼그나봇)에 **멤버 이동** 권한을 켭니다. 로비·래디언트·다이어 음성 채널이 비공개라면 그 채널에서 봇에게 **채널 보기**와 **연결**도 허용해 주세요.
2. 음성 채널 이름에 `로비`, `래디언트`(또는 `radiant`), `다이어`(또는 `dire`)가 들어 있고 그런 채널이 하나씩뿐이면 봇이 알아서 찾습니다. 찾지 못하면 `/시작`을 입력할 때 **로비**·**래디언트**·**다이어** 칸에서 채널을 골라 주세요. 한 번 정해진 채널은 봇이 기억합니다(`bot/state.json`). 바꿀 때도 같은 칸에서 고릅니다.

- `/시작`은 봇이 짠 팀 가운데 결과를 아직 기록하지 않은, 가장 나중에 짠 팀을 씁니다. 매니저에서 직접 짠 팀은 봇이 모르므로 옮기지 못합니다.
- 옮길 수 있는 사람만 옮깁니다. 로비에 없는 선수(음성 채널에 들어오지 않았거나 다른 채널에 있는 선수)는 옮기지 않고 운영진에게 알려 줍니다. 늦게 로비에 들어온 선수는 `/시작`을 한 번 더 입력하면 옮겨집니다. 쉬는 사람과 구경하는 사람은 로비에 그대로 둡니다.
- `/종료`는 봇이 짠 팀이 없어도 쓸 수 있습니다. `/승리`와는 따로이니, 결과 기록은 지금처럼 `/승리`로 합니다.

### 참여 선수 역할 자동 부여

운영진 페이지에서 **승인**한 선수에게 봇이 디스코드 역할을 주고, **제외**한 선수에게서는 뺍니다. 대기 상태는 건드리지 않습니다. `sync_url`과 `sync_key`가 있어야 합니다.

1. 디스코드 **서버 설정 → 역할**에서 봇의 역할(퍼그나봇)에 **역할 관리** 권한을 켜고, 봇의 역할을 선수에게 줄 역할보다 **위로** 끌어 올립니다. 디스코드는 봇이 자기보다 아래에 있는 역할만 주고 뺄 수 있게 합니다.
2. 관리자 채널에서 `/선수역할`을 입력하고 **역할** 칸에서 줄 역할을 고릅니다. 바로 한 번 맞추고 결과를 알려 줍니다.
3. 그 뒤로는 봇이 켜져 있는 동안 1분마다 등록 명단을 보고, 승인·제외가 바뀐 선수의 역할을 맞춘 뒤 관리자 채널에 알립니다.

- 선수는 등록할 때 적은 디스코드 사용자명(또는 숫자 ID)으로 찾습니다. 서버에 들어와 있지 않거나 사용자명을 잘못 적은 선수는 "찾지 못했어요"로 알리고 10분마다 다시 찾아봅니다. `/선수역할`을 다시 입력하면 기다리지 않고 바로 다시 찾습니다.
- 봇이 꺼져 있는 동안 승인한 선수는 봇을 켜면 처리됩니다.
- 새 시즌을 시작하면 지난 시즌 명단에 있던 선수의 역할을 모두 거둡니다. 봇이 꺼져 있는 동안 시즌이 넘어갔으면 다음에 켰을 때 거둡니다. 새 시즌에 이미 승인된 선수는 그대로 두고, 그 뒤로는 새 명단에서 승인한 선수에게 다시 줍니다.
- 봇은 누가 역할을 갖고 있는지를 디스코드에서 직접 볼 수 없어서(디스코드가 따로 허락해야 하는 권한입니다) 등록 명단으로 찾습니다. 그래서 등록한 적 없이 손으로 역할을 받은 사람은 거두지 못합니다. 그런 사람은 직접 정리해 주세요.
- `/선수역할 끄기:True`로 꺼 둔 동안 시즌이 넘어간 것은, 다시 켜도 거두지 않습니다.
- 끄려면 `/선수역할 끄기:True`를 입력합니다. 이미 준 역할은 그대로 둡니다.
- 정한 역할은 `bot/state.json`에 남아서 봇을 껐다 켜도 이어집니다. `config.json`에 `"player_role_id": 역할ID`를 적어 두는 방법도 있습니다(`/선수역할`로 정한 값이 먼저입니다).

### 자동 팀 편성과 결과 기록

`sync_url`과 `sync_key`가 있고 컴퓨터에 [Node.js](https://nodejs.org)가 설치돼 있으면, 봇이 마감할 때 팀까지 짜서 모집 글에 올리고, 경기가 끝난 뒤 `/승리`로 결과를 기록합니다. 팀 편성과 MMR 정산은 리그 매니저 파일 안의 로직을 그대로 실행하므로(`bot/matchmaker.js`), 매니저에서 **팀 짜기**와 승리 버튼을 누른 것과 같은 기준입니다.

- 봇은 서버에 있는 리그 기록(MMR, 지망, 판수)으로 팀을 짭니다. 승인한 선수는 매니저에 불러와야(선수단에 있어야) 봇이 압니다.
- 참가자가 10명을 넘으면 오늘 한 판도 뛰지 않은 사람이 먼저 출전하고, 그 안에서는 총 판수가 적은 사람이 먼저입니다. 오늘 안 뛴 사람만으로 10명이 넘어도 판수가 적은 사람부터 뽑습니다. 판수까지 같아 다 넣을 수 없을 때만 지망과 균형이 잘 맞는 쪽을 고릅니다. 하루는 오전 6시에 바뀝니다.
- 팀 편성 공지는 이런 순서입니다. 선수는 닉네임 없이 디스코드 멘션으로만 적습니다.
  1. 팀마다 평균 MMR과 다섯 자리: `` `1 캐리(1지망)` · @선수 · 인하우스 MMR · (+이기면 얻는 점수 / −지면 잃는 점수) ``
  2. 이번 판에 쉬는 사람, 선수 등록이 확인되지 않아 빠진 사람
  3. MMR 비교: 팀 평균 → 1~5번 같은 자리끼리 → 탑 라인(래디언트 3·4번 대 다이어 1·5번) → 봇 라인(래디언트 1·5번 대 다이어 3·4번). 줄마다 `` `1 캐리`(🔴 328) · @래디언트(5437) vs @다이어(5765) `` 꼴이고, 괄호 안의 🟢는 래디언트가, 🔴는 다이어가 그만큼 높다는 뜻입니다.
- 공지의 숫자는 매니저의 보드에 보이는 값과 같습니다. 팀 평균은 자리별 배율과 지망을 반영한 값이라, 다섯 명의 MMR을 그대로 평균 낸 것과 조금 다를 수 있습니다.
- 선수단에 없는 참가자(등록·승인되지 않았거나 디스코드 사용자명이 다른 사람)는 팀에서 빠지고, 공지에 따로 적힙니다.
- `/승리`는 공지된 편성 그대로 기록합니다. 대타가 뛰었거나 자리를 바꿔 뛰었다면 `/승리` 대신 매니저 팀 편성 탭의 **봇이 짠 팀 불러오기**로 편성을 올린 뒤, 고쳐서 승리 버튼을 누르세요.
- 결과를 기록하지 않고 다음 `/내전생성`을 하면 봇이 알려 줍니다. `/승리`는 결과를 기다리는 판 가운데 가장 먼저 짠 판에 적용됩니다.
- 팀만 짜고 경기를 하지 않은 판(사람이 빠져서 깨진 판 등)은 `/취소`로 취소하거나, 이미 다음 모집을 만들었다면 `/승리`에서 **경기 안 함**을 골라 정리하세요. 그대로 두면 다음 `/승리`가 그 판에 적용되고, 그 판의 열 명이 "오늘 뛴 사람"으로 남아 다음 출전 순서에서 밀립니다.
- 봇은 참가자를 디스코드 계정으로 선수와 맞춥니다. 선수단에 디스코드가 적혀 있는 선수는 그 계정으로 `/참여`했을 때만 그 선수로 봅니다(서버 별명을 다른 선수의 닉네임으로 바꿔도 그 선수가 되지 않습니다). 디스코드가 비어 있는 선수만 서버 별명과 닉네임이 같을 때 맞춥니다. 선수가 디스코드 사용자명을 바꿨다면 매니저 선수단 탭의 디스코드 칸을 고쳐 주세요.
- 끄려면 `config.json`에 `"auto_match": false`를 넣습니다. Node가 다른 곳에 있으면 `node_path`에 경로를 적습니다.

## 5. 시즌 운영 흐름

1. 운영진 페이지에서 시즌을 정하고 **등록 열기** 상태인지 확인한 뒤, 디스코드에 등록 페이지 주소를 공지합니다.
   - 첫 시즌은 **시즌 이름**을 고쳐 쓰면 됩니다(**이름만 고치기**: 이름만 바뀌고 명단은 그대로).
   - 다음 시즌부터는 **새 시즌 시작**에 이름을 넣고 누릅니다. 바뀌는 것들을 정리한 확인 창이 뜨고, 거기에 **시즌 변경**이라고 직접 입력해야 시작됩니다. 시작한 뒤에는 이전 시즌으로 되돌릴 수 없습니다.
     - 등록: 구글 시트에 `선수등록 (시즌 이름)` 탭이 새로 생기고 등록을 빈 명단에서 다시 받습니다. 지난 시즌 명단은 그 시즌의 탭에 그대로 남습니다.
     - 순위와 경기 기록: 끝난 시즌의 리그 기록을 드라이브에 `인하우스_리그기록_시즌이름.json`으로 따로 보관하고, 시트의 **순위**·**경기 기록** 탭에도 그 시즌 이름을 붙여 남깁니다. 새 시즌은 선수와 경기가 없는 기록에서 시작합니다(매니저의 설정은 그대로). 매니저를 열면 빈 기록을 받아 옵니다.
   - 지난 시즌에 참가한 선수도 같은 등록 양식을 씁니다. **스팀 프로필과 디스코드가 지난 시즌에 승인된 등록과 모두 같으면** 서버가 같은 선수로 알아보고, MMR 칸에 적어 낸 현재 MMR 대신 **그 시즌이 끝났을 때의 인하우스 MMR**을 넣습니다. 닉네임, 포지션 순서, 최고 MMR은 새로 적어 낸 값을 씁니다. 명단에는 **재참가** 표시가 붙습니다.
   - 둘 중 하나만 같으면(디스코드 사용자명을 다르게 적었거나 계정이 바뀐 경우) 다시 확인하라는 안내와 함께 등록을 받지 않습니다. 디스코드 계정이 정말 바뀐 선수는 시트의 지난 시즌 탭에서 그 선수의 **디스코드** 칸을 새 사용자명으로 고쳐 주면, 다시 등록할 때 같은 선수로 알아봅니다. 지난 기록과 잇지 않고 새 선수로 받으려면 지난 시즌 탭에서 그 줄의 **상태**를 승인이 아닌 값으로 바꿔 주세요.
   - 지난 시즌에 등록만 하고 승인되지 않았던 사람은 처음 온 선수와 같이 받고, 비고에 그때의 상태를 적어 둡니다.
2. 운영진 페이지에서 등록자를 확인하고 **승인** 또는 **제외**를 고릅니다. 봇에 `/선수역할`을 정해 두었으면 디스코드 역할은 봇이 주고 뺍니다(4. 디스코드 봇의 "참여 선수 역할 자동 부여"). 승인하거나 제외한 뒤에는 선수가 등록 정보를 직접 고칠 수 없고, 고치게 하려면 상태를 **대기**로 돌려 줍니다.
3. **매니저용 명단 받기**로 파일을 받아 매니저 선수단 탭의 **CSV 파일 고르기**로 불러옵니다. 시즌 중에 새로 승인한 선수가 생기면 같은 방법으로 다시 불러오면 새 선수만 더해집니다. 명단의 MMR이 새 시즌 인하우스 MMR의 출발점입니다(재참가 선수는 이어받은 값).
4. 내전마다: 관리자 채널에서 `/내전생성` → 마감 시각에 봇이 명단과 팀 편성을 공지(인원이 부족하면 `/연장`) → 선수들이 로비 음성 채널에 모이면 `/시작`으로 팀 채널로 이동 → 경기 후 `/종료`로 모두 로비로, `/승리`로 이긴 팀 기록. 순위 페이지와 시트에 바로 반영됩니다. 봇이 팀을 짜지 못했을 때는 매니저 팀 편성 탭의 **디스코드 봇의 참가 명단·짠 팀 불러오기**에서 명단을 불러오거나 붙여넣기 → **팀 짜기** → 경기 후 승리 팀 기록.
5. 가끔 매니저를 열어 위쪽 **기록 저장**으로 백업 파일을 받아 둡니다.
6. 등록 기간이 끝나면 운영진 페이지에서 **등록 닫기**를 누릅니다.

## 보안과 개인 정보

- 등록 정보(스팀, 디스코드)는 운영진 구글 시트에만 저장됩니다. 시트를 공유하지 마세요. 시트의 **순위** 탭에도 선수의 디스코드가 들어 있습니다.
- 리그 기록의 원본(선수의 디스코드·스팀 포함)은 운영진 구글 드라이브의 `인하우스_리그기록.json` 파일에 있습니다. 이 파일도 공유하거나 지우지 마세요.
- 공개 순위 페이지에는 닉네임, MMR, 지망, 전적, 경기 기록만 올라갑니다. 서버에서 한 번 더 걸러냅니다.
- 운영진 키가 새어 나갔다면 Apps Script 편집기에서 `resetAdminKey`를 실행해 새 키를 만들고, 운영진 페이지·매니저·봇의 키를 바꿉니다.
- 같은 스팀 프로필은 처음 등록한 디스코드 계정으로만 고칠 수 있고, 닉네임은 다른 선수와 겹칠 수 없습니다. 디스코드 계정이 바뀐 선수는 시트에서 직접 고쳐 주세요.
- 선수가 등록 정보를 직접 고칠 수 있는 것은 운영진이 승인하기 전(대기)까지입니다. 승인하거나 제외한 등록은 잠기고, 운영진 페이지에서 상태를 대기로 돌리면 다시 고칠 수 있습니다.
- 스팀 계정은 주소 모양(`/profiles/숫자`, `/id/이름`)과 상관없이 바뀌지 않는 고유 번호로 저장합니다. 등록할 때 서버가 스팀에서 확인하므로 없는 프로필은 등록되지 않고, 선수가 스팀 주소를 바꿔도 같은 계정으로 알아봅니다.
- MMR이 사실인지, 그 스팀과 디스코드가 본인 것인지는 서버가 확인하지 못합니다. 승인할 때 운영진이 프로필을 보고 판단해 주세요.
- 등록 페이지에는 지금까지 등록한 인원 수를 보여 주지 않습니다. 인원 수는 운영진 페이지에서만 보입니다.
- 최고 MMR은 운영진이 참고만 하는 값입니다. 인하우스 MMR에는 쓰이지 않습니다.
- 끝난 시즌의 리그 기록 파일(`인하우스_리그기록_시즌이름.json`)을 지우면, 그 시즌에 뛴 선수가 다시 등록할 때 인하우스 MMR을 이어받지 못하고 그때 등록한 MMR에서 시작합니다.
- 같은 스팀 프로필로는 30초에 한 번만 제출할 수 있고, 사람 눈에 보이지 않는 칸으로 자동 입력 프로그램을 거릅니다.
- 디스코드는 지금의 사용자명(영문 소문자·숫자·밑줄·마침표)이나 숫자 ID만 받습니다. 예전 방식(`이름#1234`)은 받지 않습니다.
- 등록 양식은 로그인 없이 누구나 낼 수 있습니다. 그래서 누군가 가짜 등록을 많이 넣거나, 남의 스팀·디스코드를 적어 낼 수 있습니다. 승인 전(대기)인 등록은 같은 스팀과 디스코드를 아는 사람이 고칠 수도 있습니다. 이를 막는 것은 **운영진의 승인**입니다: 승인할 때 프로필을 확인하고, 이상한 등록은 제외하세요. 가짜 등록이 몰리면 운영진 페이지에서 **등록 닫기**를 누르고 시트에서 그 줄들을 지우면 됩니다.
- 운영진 키는 운영진 페이지와 리그 매니저를 쓴 브라우저에 저장됩니다("이 브라우저에 기억하기"를 켰을 때). 함께 쓰는 컴퓨터에서는 그 칸을 끄거나, 다 쓴 뒤 **잠그기**를 눌러 지우세요.
- 구글 드라이브의 기록 파일(`인하우스_리그기록.json`, `인하우스_공개기록.json`, 끝난 시즌의 `인하우스_리그기록_시즌이름.json`)을 휴지통에 버려도, 서버가 쓰는 동안에는 도로 꺼내 둡니다. 휴지통을 비우면 되살릴 수 없으니 이 파일들은 지우지 마세요.
- 디스코드 봇은 `@everyone`이나 역할 멘션 알림을 보내지 않도록 막아 두었습니다. 닉네임에 그런 글자를 넣어도 알림이 울리지 않습니다.

## 알아 둘 점

- 구글 서버(Apps Script)는 가끔 제때 답하지 않거나 오류 화면을 돌려줍니다. 봇은 그럴 때 조금 기다렸다가 다시 물어봅니다. 봇 창에 `참여 선수 역할을 이번에는 맞추지 못했습니다. 1분 뒤에 다시 합니다.`가 가끔 보이는 것은 그런 때이고, 저절로 다시 하니 따로 하실 일은 없습니다. `RESUMED session`은 디스코드와의 연결이 잠깐 끊겼다 이어졌다는 정상 기록입니다.
- `/승리`나 `/승리취소`가 "리그 서버가 답하지 않아 … 확인하지 못했어요"라고 답하면, 잠시 뒤 같은 명령어를 다시 입력하세요. 앞에서 올린 기록이 서버에 들어가 있으면 봇이 그것을 알아보고 쓰므로, 같은 경기가 두 번 기록되지 않습니다.
- Apps Script는 무료로 쓰는 대신 하루 실행량에 한도가 있습니다. 순위 페이지는 2분마다 새 기록을 확인하는데, 리그 규모에서는 넉넉합니다. 접속자가 많아지면 `config.js`의 `refreshSeconds`를 늘리세요.
- 서버를 연결하지 않으면 순위 페이지는 같은 폴더의 `records.json`을 읽습니다. 이때는 매니저에서 받은 기록 파일을 이 이름으로 올려 갱신할 수 있습니다.
